# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ADVAD is a 2D arcade space shooter written in GDScript for **Godot 4.7** (`project.godot` targets 4.7; CI pins `4.7.1-stable`). `docs/README.md` and `docs/AGENTS.md` still mention 4.5/4.6 — trust `project.godot`. The renderer is `gl_compatibility` (the "Forward Plus" feature tag is misleading), with a 520x300 base viewport stretched via `canvas_items`.

## Agent rules (from `docs/AGENTS.md` and `docs/README.md`)

1. **No Git commands.** Do not commit, push, pull, etc. Version control is handled by the developer.
2. **Ask before running any terminal command.**
3. **Ask before creating or running any Python, utility, or node-search scripts.**

## Commands

There is no test suite. All CI workflows are `workflow_dispatch` only (manual).

```bash
# Lint (gdtoolkit: pip install gdtoolkit) — same as .github/workflows/gdlint.yml
gdlint . --exclude addons/
gdlint Scripts/player.gd            # single file

# Run the game / a single scene
godot --path .
godot --path . res://Scenes/arena2.tscn

# Import assets headlessly (CI runs this twice; the second pass is needed for heavy audio)
godot --headless --editor --quit

# Export (preset names: "Web", "Android", "iOS", "Windows Desktop", "Linux")
godot --headless --export-release "Web" build_web/index.html
```

`export_presets.cfg` is gitignored; CI recreates it from the `EXPORT_PRESETS_CFG` secret. The game has no server or online features (the old backend, leaderboard and pilot-name checks were removed).

## Architecture

### Autoloads (`project.godot` `[autoload]`)

Global state and cross-scene services live in autoloads. Several are registered by UID or under a name that differs from the file:

- `GameManager` (`Autoloads/game_manager.gd`) — the hub. Score, `phase_to_start`, `current_arena_index`, pause, feature/debug flags, speedrun timer, save/load (`user://save_game.json`; web builds persist only the pilot name), glitch transition helpers (`play_glitch_effect`, `freeze_frame`/`unfreeze_frame`), and preloaded `PackedScene`s for the heavy scenes. Arena tracker: `visited_arenas` (sorted arena indices, always has 0, saved as `visited_arenas`) gets each arena's index from `main.gd._ready` via `mark_arena_visited()` (saves only when new); `has_visited_arena()` reads it. Older saves get arena 1 from the `arena_2_reached` achievement at boot.
- Pilot name: `GameManager.player_name`, typed in the skin selector's `NameLineEdit` (Enter or `SubmitButton` saves it, "NAME SAVED!"), local only (saved as `pilot_name`; no checks, no lock).
- The chat console (`Scenes/ai_console.tscn` inside `Scenes/UI/ai_console_subviewport.tscn`, script `Scripts/ai_console.gd`) is local, framed like the credits panel over the skin selector's background (`skinpanel3.png`, same placement, dimmed by a `Backdrop`) (`credits_panel.png`, title in the top tab, close top-left, log that always scrolls to new text (`_scroll_to_bottom`), divider and a plain terminal input line: Linux prompt `adnex@sim:<path>$` + unstyled `LineEdit`, no send button, Enter only (`keep_editing_on_text_submit` keeps the phone keyboard open; `_busy` ignores Enter while output prints); nodes reached by unique name), with predefined replies for easter eggs (`replies` / `unknown_reply` exports, matched case- and space-insensitively) and secret codes that unlock achievements (`achievement_codes`, exact case-sensitive match: `6e9QhPsPapmHPv` = base58 of "deatharena", the base64 of arena 2's win code `>ZGVhdGhhcmVuYQ==`, unlocks the hidden MANUAL `death_arena_code` CODEBREAKER, ship 07; `58` replies with a hint). `ls`/`cd`/`pwd`/`cat`/`sudo` go to a fake shell, `Scripts/UI/sim_terminal.gd` (`SimTerminal`: read-only filesystem in `FILES`, home `/home/adnex`, `.classified` is locked, `sudo pacman -Syu` prints a fake Arch upgrade log, `fastfetch`/`neofetch` prints system info next to an ASCII ship 01 (`SHIP_ART`) laid out as a BBCode table, one cell per character with spaces as invisible `#`, because Kenney Pixel isn't monospaced (the log has `table_h/v_separation = 0`); `run()` returns BBCode lines and float pauses, the input prompt shows the current directory; code minigames live in `Scripts/UI/terminal_games.gd`, preloaded as `TerminalGames`: `vim` (escape it), `wat` (guess the output), `bin` (base conversion speedrun), `hack` (Wordle-style hex key) and `bughunt` (find the buggy line), listed as empty files in `/usr/games` (`vim` in `/usr/bin`) and started by name or path; while one runs it gets every raw input line, and `quit`/`exit`/`:q` leaves any but vim; the real-time ones, `invasion` (fixed shooter), `dash` (auto-runner) and `boom` (raycaster FPS, the "runs on everything" joke; typing `doom` hints at it), are `Scripts/UI/Games/console_*.gd` on the `console_game.gd` base (`intro()`/`start()`/`tick()`/`_draw()`, `finished(lines)`, keyboard via the Move_*/Shoot/Skip actions plus touch zones and an [x] corner for phones): `ai_console.gd._run_arcade` draws one over the hidden log, disables the input line and Esc quits the game before the console), opened only from the half-hidden `ChatConsoleButton` in the skin selector's bottom-right corner (`skin_selector.tscn`, faint until hovered, no keyboard focus; `chat_console_scene` export) and its back button returns to the skin selector.
- `SkinManager` — ship list and the selected ship (`selected_ship_index`, `ship_selection_changed`). Ship data lives here, not in `GameManager` as `docs/AGENTS.md` says. `selected_ship_index` is what the skin selector shows; `equipped_ship_index` is what the player flies and what gets saved (only unlocked ships). Ships are locked by default: `is_ship_unlocked()` is true only for `default_unlocked_ships`, ships whose rewarding achievement is unlocked, or everything when `unlock_all_ships` is on. The selector covers locked ships with a padlock (`LockIcon`). Ship colours (Geometry Dash style): the ship sprites themselves are black and white, and `Shaders/ship_color.gdshader` paints them by grey value: black (0–24) = outline, mid grey (48–140) = colour 1 / body, light grey (160–255) = colour 2 / details, darker grey inside a band = shadow, any non-grey pixel keeps its own colour. New ship sprites must be drawn in those grey bands (they must match the shader constants); the coloured originals are backed up in `tools/ship_originals/` (has a `.gdignore`). A ship shown without that shader looks black and white. Anything that shows a ship calls `SkinManager.apply_ship_colors(node, ship_index)` (player, selector preview, shop). The player's `EngineTrail` and dash particles (`dash_particles.tscn`) have grey colour ramps and `player.gd` tints them with colour 1 through `self_modulate` (`_particle_color()`). Colours come from `Resources/ship_color_palette.tres` (`ShipColorPalette`: colors/names/prices, price 0 = free), are global for every ship, picked in the selector's colour panel and saved by GameManager (`ship_color1`/`ship_color2`). Paid colours are sold in the shop: ShopManager creates one `COLOR` ShopItem per paid colour.
- `AchievementManager` (`Autoloads/achievement_manager.gd`, registered before `GameManager`) — loads every `Achievement` resource (`Scripts/Achievements/achievement.gd`) from `res://Resources/Achievements/`. Gameplay feeds stats with `add_stat()` / `submit_best_time()` / `raise_stat()` (mirrors a count kept elsewhere, e.g. the `deaths` stat follows `GameManager.deaths_count`, capped at 9999, for the "die 1000 times" achievement) or calls `unlock()`; progress lives in `user://achievements.json` (not saved on web). Unlocking an achievement with `reward_ship_index` unlocks that ship (`is_ship_reward_unlocked`). `GameManager.achievements_enabled` only shows the main menu button and the unlock toast. The button opens its own scene, `Scenes/achievements.tscn`, whose rows are built by `Scripts/achievements_screen.gd` from the loaded achievements. Arena clear times come from `begin_arena_run` (main.gd, phase 1 only) and `complete_arena_run` (PhaseManager), which also counts every clear in `arena_<n>_clears` (main mode only; arcade never clears an arena). `main.gd` unlocks the MANUAL `arena_2_reached` achievement (NEW GROUND, ship 27) when arena 2 loads, and `arena_3_reached` (FINAL FRONTIER, ship 31, icon `icon_arena3.svg`) when arena 3 loads. `gemela_defeated` (GEMELA DOWN, ship 4, icon `icon_gemela.svg`) reads the `gemela_kills` stat, added by PhaseManager's `boss_defeated_stat` when GEMELA is beaten (arena 3 is only cleared after the phases that follow).
- `ArcadeManager` (`Autoloads/arcade_manager.gd`, after `GameManager`) — arcade mode: an arena with no phase limit, started from the main menu's play-mode picker (the arrow on PLAY, `PlayModeArrow`, opens `PlayModePanel` with NORMAL/ARCADE; PLAY itself always starts the main mode) via `start_run(arena)`. Arenas with an arcade scene are listed in `ARCADE_ARENAS` / `get_arena_scene()` (the `GameManager.preloaded_*` scenes, because the arenas link back to the menu); arena 1 is always playable, the others once `GameManager.has_visited_arena()` (`get_available_arenas()`). With more than one available, ARCADE opens an `ArenaPicker` built in code by `main_menu.gd` inside `PlayModePanel` (so it shares its scale), to its right and exactly as tall: containers hold the arena buttons (sharing that height) and a preview of the hovered/focused arena, its background (`ArcadeManager.ARENA_PREVIEWS`) cropped to `PREVIEW_REGION` and downscaled once on the CPU (Esc closes it first); with one it starts arena 1 directly. `GameManager.arcade_mode_active` marks the run; `GameManager.arcade_enabled` shows the arrow. Every `GameManager.add_score()` also emits `points_added`; ArcadeManager multiplies those points into a separate run score (kill-chain multiplier, `combo_window` / `kills_per_step` / `max_multiplier`), so phase goals still use the raw `GameManager.score`. Every `points_per_diamond` run points pay a diamond. A death (main.gd) or timeout (PhaseManager) calls `end_run()`, which sets `phase_to_start = 1`; the reloaded HUD shows the summary (`take_last_results()`) only after the first death of each arcade session. Best score/phase are kept per arena (`records`, `get_best_score(arena)`) and go to `user://arcade.json` (`{"last_arena", "arenas": {"0": {...}}}`; the old top-level `best_score`/`best_phase` loads as arena 1). Its HUD is `Scripts/arcade_hud.gd` (the `ArcadeHud` node in `hud.tscn`, built in code, hidden outside arcade).
- `CurrencyManager` (`Autoloads/currency_manager.gd`) — the diamonds wallet (`add_diamonds`, `spend_diamonds`, `can_afford`, `diamonds_changed`), capped at `MAX_DIAMONDS` (1,000,000; diamonds earned past it are lost, a saved wallet over it loads capped), saved to `user://wallet.json` (not on web).
- `ShopManager` (`Autoloads/shop_manager.gd`, registered after `AchievementManager` and before `GameManager`, because `load_data()` asks SkinManager about owned ships) — loads every `ShopItem` resource (`Scripts/Shop/shop_item.gd`) from `res://Resources/Shop/` and sells them through CurrencyManager; progress in `user://shop.json` (not on web). `UPGRADE` items have one price per level; powerup spawners (`power_up_1_spawner.gd`, `laser_shield_spawner.gd`, `quad_laser_spawner.gd`) with a matching `@export var upgrade_stat` (`shield`, `timewarp`, `ally_saw` in `main.tscn` and `arena2.tscn`; `quad_laser` only in `arena2.tscn` and `arena3.tscn`; `triple_shot` only in `arena3.tscn`) get a shorter interval from `get_powerup_interval()`, in arcade mode only (their shop cards carry an orange "ONLY ARCADE" tag over the icon, `_add_arcade_tag` in `shop_screen.gd`). `MYSTERY_SHIP` gives a random ship that is locked by default, not an achievement reward and not in `reserved_ship_numbers` (by ship number: ships kept for future achievements plus every achievement reward ship, as a backup if an achievement fails to load; a new reward ship goes there too); owned ships count in `SkinManager.is_ship_unlocked()`. The shop scene is `Scenes/shop.tscn` / `Scripts/shop_screen.gd` (3 cards per page with arrows, on desktop buying needs two presses on the same card; with `mobile_mode_active` a tap only selects and the `BuyButton` under the cards buys), opened by the main menu's `ShopButton` (`GameManager.shop_enabled`).
- `ShaderManager`, `WebOptimizer`, `MobileOptimizer` — platform degradation, see below.
- `EnemyLaserPool` — object pool for enemy lasers.
- `CursorManager` (`Autoloads/cursor_manager.gd`) — custom hardware mouse cursor: a pixel-art arrow drawn from the `ARROW` character map (no image file), scaled by the same whole factor as the game's pixels and rebuilt on window resize; lighter while the left button is held. Off on phones.
- `DebugMenu` — overlay toggled by the `debug` action (Tab); other scripts feed it via `DebugMenu.track(label, value)`, `watch()`, `register_ray()`, `register_point()`.
- `MusicPlayer` (a `.tscn`), `SfxManager`, `FontManager`. `MusicPlayer.song_volume_offsets_db` (file name → dB) makes a single song quieter or louder than the rest; every volume set goes through `_song_db()`.
- `MainManager` is an empty stub. `DialogueManager`, `DiscordRPCLoader`, `_mcp_game_helper` come from `addons/`.

### Scene flow

`spash_screen.tscn` (main scene; the filename typo is real) → `main_menu.tscn` → `Abduction.tscn` → `tutorial.tscn` → `main.tscn` (arena 1) → `trigger_scene.tscn` (an `Area2D` in the arena that fades to `ending.tscn`) → `tutorial_arena2.tscn` → `arena2.tscn` → its own `TriggerScene` (`target_scene_path` overridden in `arena2.tscn`) → `test_room_cinematic.tscn` (resets `phase_to_start` to 1 and the score) → `tutorial_arena3.tscn` (arena 3 in black and white, red countdown) → `arena3.tscn` → its `TriggerScene` (`target_scene_path` overridden) → `monitor_cinematic.tscn` (the end of the simulation: the commander over `sim_monitor.png`, same script as the test room cinematic) → `credits_roll.tscn` → main menu; arenas 2 and 3 skip `ending.tscn`. `ending.gd` picks its next scene by the arena just won (`next_scene_by_arena`, index = `current_arena_index`, only arena 1 → `tutorial_arena2.tscn` now; arenas without an entry go to `next_scene`, the menu); it plays the commander's `lines` (set in `ending.tscn`, the briefing for arena 2) in a `UILayer/Dialogue` box and fades out after the last one (without lines it waits `display_duration`). The cinematics with the commander's lines share `Scenes/UI/cinematic_dialogue.tscn` (`CinematicDialogue`, `Scripts/UI/cinematic_dialogue.gd`, a box anchored to the bottom, instanced in each scene's `UILayer` under the CRT overlay): `play(lines, speaker)` types each line with a blip (translated first; every word "soldier"/"soldado", not the plural, becomes "soldier <`GameManager.player_name`>" when a pilot name is saved, `_with_pilot_name`), Enter (`Skip` action) or a tap completes the line, then advances, and `finished` fires after the last one; the scene then fades out with `close()`. Each scene keeps its lines in a `lines` export, and Esc (`pause`) skips the whole scene. `Abduction.tscn` (`Scripts/abduction_scene.gd`): the welcome lines over the cockpit illustration (opens after `dialogue_delay`), then the tutorial. `test_room_cinematic.tscn` (`Scripts/test_room_cinematic.gd`): the briefing over `Assets/Sprites/test_room.png`, which is scaled to cover the screen and pans slowly right to left. The three tutorials use `Scripts/tutorial.gd` (10 s countdown, asteroids only, background in black and white): `next_scene_path` is the arena it loads in the background, and `start_from_first_phase` (on in arena 2's and arena 3's tutorials) resets `phase_to_start` to 1 and the score, since arena 1's win leaves `phase_to_start` past the last phase.

`Scenes/credits_roll.tscn` (`Scripts/credits_roll.gd`, after the monitor cinematic): end credits that scroll up over `Starfield` (`Scripts/UI/starfield.gd`, a reusable animated pixel-art starfield drawn in code: stepped twinkling, cross sparkles, parallax drift, 45-degree shooting stars); lines come from the `credits_text` export (`# ` title, `## ` heading, `> ` small dim line for sources and licences, empty line = gap; it holds everything in the menu's credits panel, `Scenes/credits.tscn`), under a CRT overlay (ending's settings) in `UILayer`; Skip/Esc/click/tap leaves to `next_scene_path` (main menu); `end_logo` (`logoascii.png`, additive so its black background vanishes) comes up after the last line and stays in the middle while the text leaves; nothing leaves on its own (to enjoy the music): only Skip/Esc/click/tap fades out (image and music) to the menu; music is the ending's track.

Scene links are `@export var next_scene: PackedScene` set in the `.tscn`, not paths in code.

### Arenas and phases

`main.tscn` (arena index 0), `arena2.tscn` (index 1) and `arena3.tscn` (index 2) all use `Scripts/main.gd`; the only per-arena switch is `@export var arena_index`, which `main.gd` writes to `GameManager.current_arena_index` in `_enter_tree` — before `PhaseManager._ready` reads it.

`Scripts/phase_manager.gd` (a node inside each arena scene) drives the loop. Its three dictionaries — `arena_enemy_configs`, `arena_phase_requirements`, `arena_phase_durations` — are keyed by arena index, then phase 1–10, and are the place to tune difficulty. Arena 3 (`arena3.tscn`, built from `main.tscn`, background `Assets/Sprites/arena3.png`) is a triangle room: its walls are two `CollisionPolygon2D`s (`Walls/WallLeft`/`WallRight`, also reused in `LaserZone`) that follow the triangle, leave a gate in the middle of its base (closed by `WallStartBridge` + `LaserWallAnimation` until the arena is won) and a corridor down the bridge; it has no laser guns. The player starts low in the triangle (away from the boss), but in arcade and in the post-boss phases at the `ArcadePlayerStart` marker in the middle (`main.gd._place_arcade_start()`, in `_enter_tree` so the first wave already sees it; any arena can add that marker). Its own powerup is the triple shot: `TripleShotSpawner` (`quad_laser_spawner.gd`, 25 s timer, shop upgrade `triple_shot`: `Resources/Shop/triple_shot_spawn.tres`, 2 levels of 2000) drops `Scenes/triple_shot_pickup.tscn` (`laser_shield_pickup.gd`, `active_group = player_triple_shot`, icon `Assets/Sprites/triple_shot_pickup.svg`), which puts `Scenes/triple_shot.tscn` (`Scripts/triple_shot.gd`) on the player for `duration` (3 s): while it's there `player.gd`'s `shoot()` fires three lasers fanned by `spread_degrees` (three dots ahead of the nose show it, blinking at the end). It also has arena 2's `QuadLaserSpawner` (same scenes, 20 s); the quad laser's beams hurt bosses (`boss_damage` once per volley per boss, `_bosses_hit`), to give the player an edge against GEMELA. It is a boss arena: PhaseManager's `boss_scene` (`Scenes/Enemies/gemela.tscn`) and `boss_spawn` (`BossSpawn`) make the main mode a boss fight (`_start_boss_fight`: no timer or score goal, the phase and objective labels hidden so the boss's health bar takes their place; a death reloads and restarts the fight; beating it shows a red countdown in the middle of the screen (`post_boss_countdown`, 5 s, style `countdown_settings`, no new asteroids meanwhile) and then reloads the arena as normal phases: `GameManager.post_boss_phases` (session only, cleared by `reset_game_state()` and the test room cinematic, set before the countdown so a death during it lands there too) skips the boss and plays the arcade setup (mini GEMELAs, `ArcadePlayerStart`, the asteroid spawner's `arcade_wait_time`) with the main mode's rules (phase retries, phase 10 wins, `_win_arena()` opens the gate); `post_boss_countdown = 0` would win the arena at the boss like before), while arcade ignores `boss_scene` and plays the phases with the small GEMELA from `MiniBossSpawner` (`Scripts/Enemies/mini_boss_spawner.gd`, count per phase from the config's `"mini_boss"` table, read by `_get_phase_count()` like `"laser_guns"`). Both bosses use `Scripts/Enemies/saw_boss.gd` (`is_mini` for the small one): layered sprites in `Assets/Sprites/Enemies/Boss/` (`Body/Ring` with the laser vents, `Body/Star` spinning the other way, `Body/Head` with two cannons; the mini is one `AnimatedSprite2D` ring), small lasers from the vents through `EnemyLaserPool`, GEMELA's cannons fire laser-gun-style beams (walls only stop them, dash dodges; unlike the laser guns' beam the shield does NOT block them, the player dies and the shield breaks) at a random angle (not at the player) and sweep (it never hovers in place: every wander point is at least `min_wander_step` away and it keeps `attack_move_factor` of its speed while charging and firing), two more beams per shot at each `extra_beams_at` health fraction (2 -> 4 -> 6, spread around the head), phase two below `phase_two_at`; GEMELA has a checkpoint at `checkpoint_at` of its health (pulse, ring spin-up and a ring wave; the bar's notch lights up): it stores the health in `GameManager.boss_checkpoint_health`, which survives the death reload so the fight restarts from there (cleared when the boss is beaten, by `reset_game_state()` and by the test room cinematic); GEMELA adds `Scripts/UI/boss_health_bar.gd` to the HUD (drawn in cyan, so ArenaTint makes it red). The bosses are not in the `saws` group on purpose (ally saws free any `saws` area, the shield and quad laser kill them outright): they kill the player when the player's `Hitbox` enters them and take damage from `lasers` and `allies`. They are in the `bosses` group and give `get_avoid_radius()` (their collision circle, 0 while dying): enemy ships (`ship_enemy.gd`) and saws (`saw.gd`) steer away from them (`_boss_push`, within `BOSS_STEER_ZONE`) and are never closer than their `boss_margin` export (100 / 130) to the boss's edge (`_keep_out_of_bosses`), so they can't fly under them. The phase table in `docs/AGENTS.md` only describes arena 0.

- Phase start: `apply_difficulty()` lerps ship count/speed/fire rate by phase progress and pushes the result into the spawners through `configure_for_phase(max_enemies, config)`; the spawner hands the config dictionary to each enemy's `setup()`.
- Ship and saw spawners (`enemy_spawner.gd`, `saw_spawner.gd`) count live enemies against `max_enemies`; each wave (`spawn_initial_wave`, every phase start) bumps `_generation`, and `died` is connected with that generation bound, so an enemy from an earlier wave (one killed right before the phase ended emits `died` after its explosion sound, once the new wave is counted) neither lowers the new count nor triggers a respawn. Without it every phase leaked an extra enemy, which piled up in arcade. Refilling goes through `_refill()` (after a death's `spawn_timeout`, and at the end of the initial wave): `spawn_enemy()` rejects points closer than `safe_spawn_radius` (500 world units, about 125 screen pixels at the arenas' 0.25 zoom) to the player or (ships) too close to another ship, so it retries every `RETRY_DELAY` until the wave is back to the phase's count (one loop at a time). Laser guns are left out of the ships' separation check.
- Success (score reached): clear the board, set `GameManager.phase_to_start = current_phase + 1`, start the next phase in place — no scene reload.
- Arcade only: after a death or timeout no score counts (`GameManager.add_score()` returns while `can_add_score` is false, `stop_scoring()` until `reset_score()`, and `_on_score_updated` ignores updates while the player is dead), so a laser still in flight can't clear the phase and overwrite the restart from phase 1. The main mode keeps counting it on purpose: a laser that clears the phase after the death advances (a last chance for the player).
- Failure (timer out or player death): `reload_current_scene()` with `phase_to_start` unchanged, so the player retries the same phase. State that must survive the reload (`is_shader_animation`, `is_glitch_sound`, the frozen frame) is parked on `GameManager` and consumed in `main.gd._ready`.
- All phases done: spawners stop, `wall_to_remove` is freed, opening the path to the scene trigger.
- Arcade mode (`GameManager.arcade_mode_active`): every phase exists. Past the table, the score goal keeps the last step (+500 in arena 1), the duration keeps the last phase's points-per-second pace, and difficulty progress keeps growing by `arcade_overdrive_per_phase` up to `arcade_max_progress` (lerp extrapolates), except the ship count, which stays at its `arcade_ship_count_cap_phase` (8) value. No speedrun timer, no arena clear time.

Arena 2 also has laser guns: `LaserGunSpawner` (`Scripts/Enemies/laser_gun_spawner.gd`, at the scene origin, wall faces in global coordinates) puts `Scenes/laser_gun.tscn` (`LaserGun`, groups `laser_guns` + `enemies`) on the side walls. They patrol up and down, charge (blinking aim line) and fire a beam made with a `RayCast2D` that only stops at walls (`StaticBody2D`); the player is tested against their `Hitbox/CollisionShape2D` (`Shape2D.collide` with the beam as a rectangle), so a disabled hitbox (dash, debugging) is never hit, and a laser shield blocks the beam (once per shot, `_shield_blocked`, outside arcade mode it adds the `beams_blocked` stat: BEAM BLOCKER achievement, ship 35; arcade doesn't count because the shop upgrade makes shields drop more often). The beam also destroys the saws, enemy ships and asteroids it crosses (`intersect_shape`, calling their `die_and_respawn()` / `Asteroid.explode()`, which give no score or saw-achievement progress), and the player's ally saws (`allies`, `powerup1.gd`'s `die()`, only if not `is_dying`); an ally saw touching a gun destroys the gun. How many per phase comes from the arena config's `"laser_guns"` table (`{from phase: count}`, `{3: 1, 5: 2, 7: 3, 10: 4}`), read by `PhaseManager._get_laser_gun_count()`. Spritesheets in `Assets/Sprites/Enemies/`: `laser_gun_sheet.png` (10 frames of 56x32: idle 0-3, charge 4-7, fire 8-9), `laser_gun_spawn.png` (the `spawn` animation of the same sprite, 10 frames of 96x64 with the gun at the same centre; it can't be hit until it ends), `laser_gun_break.png` (death, 9 frames of 96x64) and `laser_beam_impact.png` (4 frames of 24x24 where the beam ends). The gun uses no particles. Shooting one down (player lasers only) adds the `laser_guns_destroyed` stat (GUN BREAKER achievement, rewards ship 15; its icon is an `AtlasTexture` of `laser_gun_break.png`). Its sounds are `Assets/Audio/laser_gun_charge.ogg` (0.9 s, matches `charge_time`) and `laser_gun_fire.ogg` (0.55 s, matches `fire_time`); its death sound is the enemy ships' one, played at the gun's position. Arena 2 also has the quad laser powerup: `QuadLaserSpawner` (its own `Scripts/quad_laser_spawner.gd`, 20 s timer, `upgrade_stat = quad_laser`) drops `Scenes/quad_laser_pickup.tscn` (`laser_shield_pickup.gd`, whose `active_group` export blocks a second pickup while the reward runs; icon `Assets/Sprites/quad_laser_pickup.svg`, also the shop icon of `Resources/Shop/quad_laser_spawn.tres`), which puts `Scenes/quad_laser.tscn` (`QuadLaser`, `Scripts/quad_laser.gd`, group `player_quad_laser`, built in code) on the player: four mini cannons on the ship's diagonals (they turn with it, moved to the player's first child so they draw under the ship) fire 4 beams at once, `volleys` times. Each beam is a `RayCast2D` that only stops at walls like the laser guns' beam, cast from the ship's centre (not the muzzle, which is inside or past the wall when the ship is pressed against it; `hit_from_inside` on) and drawn from the muzzle to the hit (no beam if the wall is closer than the muzzle; the lines are in the cannons' local space, so they're re-cast and redrawn every rendered frame in `_process`, while hits are tested in `_physics_process`), and an `intersect_shape` along it destroys asteroids, saws, enemy ships (scoring 50/200/100 like the player's lasers, saws also add `saws_destroyed`) and releases active enemy lasers; laser guns and ally saws are skipped. `PhaseManager.nodes_to_remove` frees extra nodes with `wall_to_remove` when the arena is won (arena 2: the `LaserZone` shape over the bridge opening).

Arena 2's background (`Sprite2D`, `arena2.png`) has a `BackgroundWaves` child (`Scripts/background_waves.gd`, `Shaders/background_waves.gdshader`): the same texture again, drawing slow pixel-grid waves only where the background is the empty `fill_color` (#000c07, the panels below the room, texture rows >= 280) and copying the background's `grayscale_amount`. The drawing itself is untouched. Arena 1 (`main.tscn`) does the same with `BackgroundClouds` (same script, `Shaders/background_clouds.gdshader`): two layers of stepped pixel clouds drifting sideways below texture row 270 of `gauntletdefinitivo5.png`, drawn only on the empty colour, which it reads from `fill_texel` (bottom-left texel); heights, colours and speeds are shader parameters.

Each arena has its own UI colour: the hidden `ArenaTint` node in `hud.tscn` (`Scripts/UI/arena_ui_tint.gd`, `Shaders/ui_hue_shift.gdshader`) hue-rotates every CanvasItem of the HUD (also ones added later) by `GameManager.arena_ui_hue_shifts[current_arena_index]` (0 = blue, -60 = green, 180 = red). Drop the same node into any other UI to tint it. `reset_game_state()` sets `current_arena_index` back to 0.

`PhaseManager` reaches HUD nodes by hardcoded relative paths (`$"../UILayer/HUD"...`), and `trigger_scene.gd` looks up `/root/Main`, so arena scenes need those node names and layout.

### Groups are the collision/interaction contract

Entities identify each other with `is_in_group` checks rather than types, and group names are a mix of Spanish and English: `asteroides`, `enemigos`, `colisiones`, `lasers`, `enemy_laser`, `saws`, `enemies`, `enemies_death`, `allies`, `player`, `player_shield`, `destructibles`, `powerup_spawners`, `time_slow_effect`. Note `enemies` (added by the spawner at runtime, used for `call_group("enemies", "die_silently")`) versus `enemigos` (checked for player body collisions). Anything in `saws`/`enemies` must implement `die_silently()`; anything in `powerup_spawners` must implement `stop()`.

### Enemy laser pooling

Enemy lasers are never instantiated or freed directly. Use `EnemyLaserPool.acquire(parent, spawn_position, fire_direction, origin)` and `EnemyLaserPool.release(laser)`; `enemy_laser.gd` implements `activate()`/`deactivate()`. Calling `queue_free()` on one breaks the pool. The laser shield re-tags a deflected enemy laser into the `lasers` group, which `enemy_laser.gd` undoes on reactivation. So anything hit by a `lasers` area must release it with `EnemyLaserPool.release()` when it `has_method("deactivate")` (a deflected enemy laser) and only `queue_free()` real player lasers (ship_enemy, saw and laser_gun do this). `enemy_laser.shooter` is the ship that fired it (set by `ship_enemy.gd`, cleared on `activate()`); a ship killed by its own deflected laser adds the `own_laser_kills` stat (RETURN TO SENDER achievement, ship 17).

### Platform degradation

One codebase serves desktop, web (single-threaded), and mobile; behavior branches at runtime on `GameManager.mobile_mode_active`, `OS.has_feature("web")`, and `GameManager.force_web_mode` (set it to test the web path on desktop).

- CRT shader (`Shaders/CRT.gdshader`): `ShaderManager` and `WebOptimizer` hook `SceneTree.node_added`, and on every scene change scan for `ShaderMaterial`s whose shader path contains `"CRT"` and set `low_quality` and related parameters. `WebOptimizer` frees itself on native builds. A new CRT-style shader needs "CRT" in its path to be picked up. The roll (bands scrolling down the screen) follows `GameManager.crt_roll_enabled` (saved), but only on the PC high-quality path; `ShaderManager.is_roll_supported()` is false on mobile/web/optimized shaders.
- Settings panel: `Scenes/UI/settings_panel.tscn` (`SettingsPanel`, `Scripts/UI/settings_panel.gd`, a `NinePatchRect`) is shared by the main menu (the gear `SettingsButton` opens it; closes on Esc or a click outside, like the play-mode picker) and the pause menu. It holds the controls, FPS, full screen, retro-shader, roll and speedrun toggles (3x2 grid), the special thanks button (under roll; `show_special_thanks`, emits `special_thanks_requested`) and two `VolumeRow`s (`Scripts/UI/volume_row.gd`: music / SFX, hold to repeat). All toggle logic lives in the panel: it writes GameManager and calls `GameManager.apply_settings()`, which saves and emits `settings_changed` (the HUD shows/hides the FPS live; emitting from GameManager itself also keeps GDScript's UNUSED_SIGNAL warning away) and re-applies CRT changes to the whole open scene with `ShaderManager.refresh_current_scene()`; `sync_with_settings()` runs on every open; `controls_changed` lets the menu show its hint label; `allow_speedrun_toggle = false` locks the speedrun toggle mid-run (the timer only starts with a run). Volume lives in `MusicPlayer.increase_volume()`/`decrease_volume()` and `SfxManager.increase_sfx_volume()`/`decrease_sfx_volume()`, which store the percentage in `GameManager.music_volume_percent`/`sfx_volume_percent` and save on every change (`music_volume`/`sfx_volume` in `save_game.json`, not on web); both managers read it back in `_ready`. The gear and roll sprites are in `Assets/Sprites/Settings/`.
- Pause menu: `Scenes/UI/pause_menu.tscn` (`Scripts/UI/pause_menu.gd`, a `CanvasLayer` on layer 5, process mode always), instanced as `PauseMenu` in `main.tscn`, `arena2.tscn`, `tutorial.tscn`, `tutorial_arena2.tscn` and `tutorial_arena3.tscn` (`palette = 2`). Terminal style: an `adnex@sim:~$ pause` header and flat text `Button`s `resume` / `settings` / `quit`, with a `>` `Arrow` label per row shown only on the focused one (mouse hover grabs focus, up/down wrap, ui_accept picks). Texts use the HUD label style (dark fill, 2 px outline) plus a glow (a centred `LabelSettings` shadow in the outline colour, `GLOW_*`); the selected row gets the bright outline, a lighter fill and the strong glow, the rest a dim outline and faint glow. Buttons can't draw a text shadow, so `_make_text_label()` moves each button's text to a `Label` child in the instance's `palette` export: `BLUE` (arena 1 and its tutorial), `GREEN` (`palette = 1` in `arena2.tscn` and `tutorial_arena2.tscn`) or `RED` (`palette = 2` in `arena3.tscn`); colours in `PALETTES`. The `Dim` backdrop is a 68 % dark tint (the game stays visible) and the list sits in `MenuPlate`, a `PanelContainer` with a `StyleBoxEmpty` (margins only, no box behind the text; the script dims it while settings is open). `settings` opens the same `SettingsPanel` beside the list (speedrun locked, no special thanks); while it's open the three rows are disabled, unfocusable and dimmed (`_set_buttons_enabled`); Esc (handled before GameManager's pause toggle) or a click outside closes it, that click is consumed, and the rows come back deferred (`_restore_buttons`, focus on `settings`) so neither the click nor a phone's emulated mouse click after a touch can press a row. `quit` unpauses, calls the scene's `reset_shader_parameters()`, resets entity colours and goes to `menu_scene` (or `main_menu.tscn` by path). It keeps the `skullIcon/Label` deaths counter that `main.gd` reads.
- Main menu PLAY / CREDITS / QUIT: `TextureButton`s in `VBoxContainer` with 50x20 pixel-art SVGs in `Assets/Sprites/MainMenu/` (`*_button.svg` normal, `*_button_hover.svg` for hover, pressed and focus; the old `playbutton.png` etc. are still used by the arenas). Each has an icon and left-aligned text on a scanlined screen; the lit version adds a halo and corner brackets. Hovering one grabs focus (`_setup_main_buttons`, not while a popup is open), so only one is lit. The arcade arrow covers PLAY's screen at x 37-43, y 5-14 (keep it clear) and swaps to its hover texture while PLAY has focus.
- Shader warm-up: at boot `GameManager` runs `Scripts/shader_warmup.gd`, which reads the preloaded scenes through `SceneState` (no instantiation), and draws one script-less "ghost" per unique drawable/material in an offscreen `SubViewport`, a few per frame, so shaders compile during the splash instead of freezing the first frame of an arena. The splash waits on `GameManager.wait_for_shader_warmup()`. Scenes spawned only via `preload()` in scripts must be added to the list in `GameManager._start_shader_warmup`.
- `MobileOptimizer` turns on `mobile_mode_active` for Android/iOS, caps the framerate to an even divisor of the screen refresh rate (60 on 60/120Hz, 90 on 90Hz) and sets the physics tick rate to match, so per-tick smoothing must be written delta-based (`1.0 - pow(1.0 - k, delta * 60.0)`), never as a fixed lerp factor, and switches the window to `CONTENT_SCALE_ASPECT_EXPAND`.
- UI is laid out with absolute coordinates for 520x300. Instead of anchors, UI scripts (`hud.gd`, `main_menu.gd`, `skin_selector.gd`, splash) store original positions and shift them by the offset from x=260 on `size_changed`. New UI nodes in those scenes follow that pattern.
- Particle scripts shorten lifetimes and arenas disable light shadows in mobile mode.

### Localization (EN / ES)

English is the default and the source text; Spanish lives in `Localization/es.po` (registered in `project.godot` `[internationalization]`), whose `msgid`s are the exact English strings. `GameManager.language` (`"en"`/`"es"`, saved as `language`, also on web) is applied with `TranslationServer.set_locale()` at boot (never the system language) and changed by `GameManager.set_language()`, which emits `language_changed`; the switch is the settings panel's `LanguageButton` (third row, right; `language_en/es(_hover).png` in `Assets/Sprites/Settings/`, showing the current language). Controls translate an exact-match text by themselves (scene texts and code-set ones like "NAME SAVED!"); text built from pieces goes through `tr()` first (`tr("PHASE: ") + str(n)`, `tr("%s UNLOCKED") % reward`) and, if it can be on screen while the language changes (pause menu), is rebuilt on `language_changed` (`score_label.gd`, `PhaseManager._update_phase_label`), and text typed out letter by letter is translated before typing with `auto_translate_mode` off on its label (`CinematicDialogue._with_pilot_name`, the shop's `_say`). So a new UI string needs its English text added as a `msgid` in `es.po`. Not translated on purpose: names (ships, authors, colours, GEMELA, ADNEX), achievement titles and shop item titles, and the secret chat console. Images with English text drawn in them get a `SpanishTextures` child node (`Scripts/UI/spanish_textures.gd`: keeps the parent's textures as English and swaps in its `normal`/`hover`/`pressed`/`focused`/`disabled`/`texture` exports in Spanish): the menu's PLAY/CREDITS/QUIT (`*_es.svg` in `Assets/Sprites/MainMenu/`, same 3x6 rect font) and the shop's BUY button and sign (`buy_button*_es.png`, `shop_sign_es.png`). NORMAL/ARCADE are the same word in both languages.

### Conventions

- Logging goes through a per-script `_log_message(message)` (string or array) that prints only when `GameManager.is_debug_text` is true. The function is copy-pasted into each script rather than shared.
- Comments and log strings are a mix of English and Spanish.
- `addons/` is third-party (Dialogue Manager, Discord RPC, godot_ai MCP plugin, kanban_tasks, git plugin) and is excluded from linting.
